# Подключение к FinancePro по локальной сети

Сервер запущен на машине **`BlackArch`** в WiFi-сети `Milleoners WIFI`. Backend
слушает `0.0.0.0:8000` (открыт для всех интерфейсов), на хосте firewall неактивен
(`firewalld`, `nftables`, `ufw` — все `inactive`).

## Куда подключаться

| Транспорт | URL для Flutter Settings → API URL | Когда использовать |
|-----------|-----------------------------------|--------------------|
| WiFi (LAN) | `http://192.168.1.42:8000` | Когда клиент в той же WiFi |
| Tailscale  | `http://100.68.45.17:8000` | Когда клиент через VPN / другая сеть |

**API Key** — значение `APP_API_KEY` из `.env` (64 символа). Тот же, что
используется локально.

> ⚠️ Адрес `192.168.1.42` выдан DHCP. Если роутер выдаст другой — обнови URL.
> Закрепить адрес: в админке роутера сделай static DHCP lease для MAC `wlan0`.

## Диагностика с Windows (если не подключается)

Открой **cmd** (Win+R → `cmd`) и проходи по шагам сверху вниз. Останавливайся на
первом, который упал.

### Шаг 1. Сетевая досягаемость

```cmd
ping 192.168.1.42
```

- ❌ **Timeout / Request timed out** →
  - Ноут не в той же WiFi (`Milleoners WIFI`).
  - **Либо** на роутере включена **AP Isolation / "Client isolation"** — частая
    дефолтная настройка для гостевых сетей. Зайди в админку роутера (обычно
    `http://192.168.1.1`) → раздел WiFi → выключи опцию "AP Isolation" /
    "Изоляция клиентов" / "Wireless Isolation".
  - **Либо** используй Tailscale: установи на Windows клиент с
    [tailscale.com/download](https://tailscale.com/download), войди тем же
    аккаунтом, и пингуй `100.68.45.17` — должен работать.
- ✅ **Reply from 192.168.1.42** → переходи к шагу 2.

### Шаг 2. HTTP-уровень

```cmd
curl -v http://192.168.1.42:8000/
```

(curl встроен в Windows 10 1803+ и Windows 11)

- ❌ **Connection refused** → backend не запущен на сервере.
  Запусти на сервере: `docker compose up -d`.
- ❌ **Timed out** → файрвол блокирует. На сервере проверь
  `sudo ss -ltn '( sport = :8000 )'` — должен быть `LISTEN 0.0.0.0:8000`.
- ✅ **JSON-ответ вида** `{"name":"FinancePro API","version":"0.1.0","status":"ok",...}` →
  сеть и backend в порядке, переходи к шагу 3.

### Шаг 3. Авторизация

```cmd
curl -H "Authorization: Bearer ВСТАВЬ_КЛЮЧ_СЮДА" http://192.168.1.42:8000/api/v1/accounts
```

- ❌ **`{"detail":"Invalid API key"}` или 401** → ключ скопирован неправильно
  (пробел, обрезка). Открой `.env` на сервере, аккуратно скопируй значение
  после `APP_API_KEY=` (64 символа без переноса строки).
- ✅ **JSON-массив с аккаунтами** → доступ полный. Открывай Flutter.

### Шаг 4. Flutter Settings

В приложении на Windows: **Settings → API URL** должно быть **строго**:

```
http://192.168.1.42:8000
```

Частые ошибки:
- ❌ `https://192.168.1.42:8000` (с `s`) — у нас обычный HTTP, без TLS.
- ❌ `localhost:8000` / `127.0.0.1:8000` — это сам ноут, не сервер.
- ❌ `192.168.1.42:8000` без `http://` — Dio не угадывает протокол.
- ❌ `http://192.168.1.42` без `:8000` — порт обязателен.

**API Key** — тот же 64-символьный `APP_API_KEY`. После ввода нажми **Save** и
полностью перезапусти приложение (не сворачивай, именно закрой и открой).

## Проверка с сервера (что я уже подтвердил)

```
=== Listening sockets ===
LISTEN 0 4096  0.0.0.0:8000  0.0.0.0:*    ← backend открыт на всех интерфейсах

=== Docker port mapping ===
backend  0.0.0.0:8000->8000/tcp

=== firewalld / nftables / ufw ===
inactive / inactive / inactive               ← никакой файрвол не блокирует

=== curl http://192.168.1.42:8000/docs ===  HTTP 200 OK
=== curl http://100.68.45.17:8000/docs ===  HTTP 200 OK  (Tailscale)
```

## Безопасность

- Backend защищён статическим Bearer-токеном (`APP_API_KEY`). Без него — `401`.
- В LAN это нормально для single-user самохостинга. **Не открывай порт 8000
  наружу через NAT** — токен не ротируется, нет rate-limiting.
- PostgreSQL **не открыт** в LAN намеренно — доступ к данным только через API.

## Если совсем ничего не работает

Скинь вывод этих трёх команд с Windows:

```cmd
ping 192.168.1.42
curl -v http://192.168.1.42:8000/
ipconfig | findstr IPv4
```

— и я скажу точную причину.
